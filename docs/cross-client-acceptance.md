## 一键运行浏览器验收

双击根目录的 `verify-cross-client.bat`。脚本依次构建并测试后端、运行前端单元测试、构建 Web、检查 PWA、启动隔离服务并运行浏览器测试。首次会安装官方 Chromium；需要 Java 21、Maven 3.9 和 Node.js 22，当前电脑可使用已配置的便携工具。

测试前端使用 43130，API 使用 43131，数据库为随机命名的 H2 内存库。端口被占用时直接停止验收，不复用或关闭其他服务。测试创建合成账号，不使用真实账号、旧版数据库或云端服务。测试结束后仅关闭自己启动的进程，内存数据随服务结束消失。

失败报告在 `web/playwright-report`，截图和追踪在 `web/test-results`。追踪可能包含临时测试账号和会话令牌，不能上传公开仓库；这些目录已被 Git 忽略，CI 不上传追踪附件。[Playwright 官方服务管理说明](https://playwright.dev/docs/test-webserver)解释了多服务启动与不复用已有服务的选项。

## 准备 Android 手机

1. 解锁手机，用支持数据传输的 USB 线连接电脑，开启开发者选项和 USB 调试，只授权自己的电脑。
2. 双击 `start-desktop-server.bat`，保持窗口打开。它只监听本机 43129，使用独立的 `backend/data/desktop-local` 测试库；只创建测试账号。
3. 先用 `build-android.bat` 构建最新包，再双击 `prepare-android-test.bat`。脚本要求恰好一台已授权设备，检查签名、建立 USB 端口转发并覆盖安装调试包，不卸载已有应用。
4. 手机上打开计划舱，在服务器设置填写 `http://127.0.0.1:43129`。这个地址通过 USB 指向电脑，不需要开放校园网端口。拔线后不能继续依赖该转发。
5. 若提示签名不一致，先保留现有应用和数据，不要卸载来强行绕过。测试包没有正式发布身份。

43129 是 API 端口，不是网页入口。不要在手机浏览器地址栏打开它；根路径未登录返回 HTTP 401 是预期行为。请从刚安装的计划舱 APK 进入，把该地址填在应用的服务器设置中。原来安装的 PWA 快捷方式不能代替本次 APK 验收。

运行 Keystore 设备测试：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/android-device.ps1 -Action instrument
```

脚本只构建并安装测试 APK，直接执行设备测试，不让 Gradle 自动卸载主应用。测试使用随机虚拟服务器标识，核对加密、重建读取、服务器隔离与删除，不访问真实账号。测试辅助包会留在设备上。它不证明登录界面、分享、返回键和后台恢复正确。

## 原生验收清单

以下项目需在实际 Windows 安装包和 Android 手机上检查并记录，尚未执行的项目不能标为通过。

- 安装与冷启动：无白屏，登录前可修改服务器地址；配置错误时明确提示。
- 会话：同账号两端登录，关闭后重开恢复会话，退出后不能恢复旧账号。
- 数据隔离：另一账号不可见原账号数据，切换服务器不提交原服务器队列。
- 三端业务：Web、EXE、APK 新增编辑计划、任务、标签和主线后互相刷新可见。
- 离线与冲突：普通编辑保留在队列，恢复网络后按序重放；冲突不覆盖其他端，后续项保持等待。计时、完成与删除必须在线。
- 手机后台：锁屏或切后台后重开，以后端状态恢复计时，不重复累计。
- 导出与操作：Android 分享可取消，中文文件正常；返回键、键盘、状态栏不遮挡保存按钮。
- 覆盖升级：同签名且更高 Android versionCode 的包保留配置与会话；Windows 手动覆盖安装后验证数据。不要用卸载重装代替升级测试。

当前尚未完成 versionCode 3 离线工作区全部真机复测、Windows 覆盖升级回归、iOS Safari 回归与正式签名发布。versionCode 3 已通过缓存浏览与离线重开，用户随后确认计划离线编辑成功。日程出现“此内容尚未缓存，请联网加载后再离线查看”，尚需用同一计划、同一日期范围联网加载后再断开服务器核对；目前不能确定缺失缓存的具体查询，也不能将日程缓存复测列为通过。日程执行状态、计时、补做与实际用时保存仍要求联网，不属于离线编辑范围。安装调试 APK 不需要等待公安备案或公网证书；连接公网新版 API 时才需要有效 HTTPS 证书和已验收部署。

## 休息日配置与独立真机测试

新计划可以多选每周休息日，默认不选，表示没有固定休息日。进入计划任务页，点击“编辑计划设置”可再次调整。日程根据当前计划的配置标记休息日；这些日期仍能安排任务和补做，不过滤、移动或删除已有任务。配置也支持离线编辑，保存后标为待同步，冲突仍需用户处理。

API 的 `restDays` 使用 ISO 星期编号：1 为周一，7 为周日。`[]` 明确清空休息日；更新请求省略该字段时保留现有配置。Flyway `V11` 为旧计划加入空配置，不默认继承周六、周日。H2 的升级迁移已通过测试，MySQL 实际迁移尚未演练。旧服务器没有相应能力时，客户端会阻止保存休息日，避免显示成功却未写入服务器。

当前 43129 服务使用内存测试库，仍保留原有测试账号与计划，不能为升级而直接关闭。新版真机验收使用另一个持久化测试库：

1. 双击根目录 `start-rest-days-test-server.bat`，保持窗口打开。新服务只监听 `127.0.0.1:43132`，数据库为 `backend/data/rest-days-test`，不会复用或关闭 43129 服务。
2. 手机连接 USB 并授权后，双击 `prepare-rest-days-test.bat`。它检查新服务、验证 APK 签名、建立 43132 转发，再用覆盖安装方式安装当前测试包；不会卸载应用或清除其数据。
3. 在 APP 的服务器设置保存 `http://127.0.0.1:43132`，在这个独立环境创建合成测试账号。这里不会自动迁移 43129 的账号或计划，也不会提交旧服务器的离线队列。
4. 创建测试计划，选择周一休息，再进入“编辑计划设置”改为周六；打开同一计划与同一日期范围的日程，确认标签变化且已有任务保留。
5. 暂停 43132 USB 转发后，检查已缓存日程，离线修改休息日并重开 APP；恢复转发、验证账号，再手动同步等待项。分别记录缓存浏览、配置投影和服务器提交结果。

切换服务器会要求重新登录；先确认原服务器待同步项的情况，不能将切换当作原数据已经迁移。

2026-10-03 用户已完成此轮真机验收：创建与二次编辑休息日正常；离线重开仍保持星期日休息、任务保留，队列为 1 项操作与 0 项冲突；恢复连接并同步后为 0 项操作与 0 项冲突。PC 最初仍显示周六、周日休息，定位为安装了旧 EXE；覆盖最新 0.1.0 测试包后，用户确认只有周日休息、周六为计划日、原任务仍在。后续的 0.1.1 应用内更新验收另见 [客户端更新与本地验收](client-updates.md)，不可将上述覆盖安装结果当作应用内升级通过。
