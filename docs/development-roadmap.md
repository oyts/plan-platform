# 计划舱后续开发规划

规划日期：2026 年 10 月 18 日。基线为已发布的 `0.1.14`，Android 构建号 `19`。本文是待实施的阶段规划，不表示以下功能已经开发，也不授权自动开启公开注册、公开 APK、购买资源或清理旧数据。

接下来先把受邀朋友试用、问题反馈、数据可带走和长期使用做成闭环，再考虑更多客户端。默认从阶段一开始，按完整阶段开发完毕后集中验收；严重的数据丢失、越权、签名或备份故障优先修复，不等待排期。

## 阶段一 试用反馈与脱敏诊断

### 目标与交付

让“朋友告诉我不能用”变成能够定位、沟通和关闭的问题。Web、Windows、Android 共用反馈入口，放在“更多／帮助”中。

- 用户填写问题类型、复现步骤、预期和实际结果，并查看自己反馈的状态及管理员处理回复。
- 提交前预览可选诊断摘要：客户端与 API 版本、平台、发生时间、错误分类、请求关联编号、队列数量。默认不附带业务正文或原始日志。
- 管理员按新建、处理中、需补充、已解决、已关闭处理反馈，普通用户不能查看他人反馈。
- 服务器不可达时仍能在本机保存反馈草稿、复制或导出诊断摘要，恢复后由用户确认提交；不偷偷后台上传。
- 连接错误区分网络不可达、TLS、登录过期、权限、版本不兼容、服务繁忙及业务校验失败，保留必要的恢复操作；不以换文案代替连接修复。

### 边界与验收

首版不做附件、自动截屏、聊天系统或外部工单服务。诊断不收集密码、令牌、Key、邀请链接、AI 原文、任务标题、设备序列号或完整私人网络地址。用户主动填写的文字也可能含隐私，提交前明确提醒和确认。

验收包括三端同一条合成反馈的提交与查看、管理员处理、账号隔离、无网草稿、脱敏内容白名单和重复点击防重。不发送真实朋友的内容作为测试数据。该阶段完成后，后续功能可直接使用此入口收集反馈。

## 阶段二 个人数据中心

### 目标与交付

在已有导出中心上扩展，不再局限于周期计划。区分“可阅读导出”和“可恢复备份”：CSV/Markdown 便于阅读，带 `schemaVersion` 的私有 JSON 用于关系完整的恢复。

- 补齐目标路线的阶段、步骤和依赖、今日待办、周复盘的导出，保留现有周期计划与计时导出。
- 定义新版备份格式，覆盖本人的计划结构、休息日、任务进度与保留流水、路线关系、待办和复盘；不把运行中的计时器恢复为正在运行。
- 明确列出不包含的内容：账号密码、会话、邀请、签名材料、服务器配置、API Key、AI 对话和本机未提交队列。提醒偏好可选择导出，但导入不自动开启提醒。
- 先提供格式预检、关系完整性检查和数量预览，再提供明确确认后的恢复。默认导入为新记录，不覆盖现有内容；重新映射 ID、所有权和关联关系。
- 超限文件、非法引用、循环依赖、版本不支持或重复批次有明确结果；恢复原子提交，不能留下半套计划。

### 边界与验收

这是当前账号的业务数据备份，不替代生产 MySQL/OSS 备份，也不承诺迁移其他软件的任意文件。云端导出只包含已同步数据；有队列时明确提示，不清队列来导出或恢复。恢复必须联网；备份文件含私人内容，应明确提醒妥善保存。CSV 处理表格公式注入风险，下载链接不公开。

用合成账号验证导出 → 预检 → 另一合成账号恢复的完整关系、中文、完成时间、计时历史和依赖；验证重复导入不重复建数据、失败整批回滚、他人数据不可访问及现有内容不被覆盖。以这些结果作为后续结构复制的格式基础。

## 阶段三 高效编排与长期目标

### 目标与交付

把已经做好的结构重复利用起来，并让长期路线适合“闲时多做、忙时暂停”的真实节奏。

- 整套周期计划和目标路线结构复制：可调整周期、休息日或名称，默认不复制完成状态、执行历史和实际用时。
- 复用现有模板和重复规则，新增未来、未开始实例的日期、时长和标签批量调整；先预览差异、数量及不受影响的历史，再确认应用。
- 路线级暂停与恢复，和步骤计时暂停、归档、回收站清楚区分。遇到正在计时的步骤应先明确处理，不静默丢失时间；暂停不删除阶段、依赖或历史。
- 待办和长路线增加服务端分页、搜索及历史查询。前端展示分页不再冒充服务端分页；依赖与解锁仍由后端依据完整关系校验。

### 边界与验收

目标路线仍不强加截止日期。批量改期不因休息日自动删除或移动真实任务，日期规则须在预览中说明。只改明确选择且允许修改的事项，已完成、已有计时或验收历史默认受保护；版本冲突整批拒绝，重复确认幂等。

验收覆盖复制关系、受保护历史、批量变更原子性、409、路线暂停恢复、分页搜索及旧客户端兼容。结构复制不等于跨账号分享，公共模板市场不在本阶段。

## 阶段四 跨端离线与冲突体验

### 目标与交付

扩展现有离线机制，不重写一套同步系统。

- 提供可见的缓存范围和状态，允许选择有限日期范围预先加载，说明大小、有效期及尚未缓存内容。
- 先补周复盘等页面的本机未提交草稿保存与重开恢复。界面区分“已存本机”“已提交云端”“需要处理”，本机草稿不冒充跨端已同步。
- 同步中心以普通用户能理解的字段展示本机修改与最新云端内容；有共同基础版本时才显示可靠的三方差异，否则明确只显示双方差异。
- 用户保留或摘取需要的内容后，基于最新版本生成新的修改并确认提交；不静默采用最后写入者，不自动覆盖已变化记录。

### 边界与验收

AI、计时结算、删除和账号安全等在线操作不因本阶段自动开放离线。周复盘云端保存、提醒偏好修改仍需联网；若以后加入离线重放，必须单独定义版本与幂等协议。暂不承诺延长现有 24 小时离线身份期限，也不部署客户端大模型。

集中测试断网保存与重开、缓存范围、迟到响应、账号／服务器切换、真实 409、用户确认重提及升级保留非空合成队列；不操作用户真实冲突，不以清数据解决问题。

## 阶段五 轻量运维与账号治理

### 目标与交付

在现有 2 核 2GB ECS 和备份体系上补齐可持续运行能力，不默认增加付费产品。

- 显示备份最近成功时间、OSS 上传校验、最近恢复演练和磁盘状态；对失败或长期未成功提供去重告警，避免告警风暴。
- 先提供备份清理预览，再由维护者确认本地与 OSS 保留策略。验证新备份和恢复路径后才执行有限清理，不删除唯一可恢复点、签名材料或旧发布回滚材料。
- 增加成员停用／恢复与敏感操作审计，明确对已签发令牌的生效方式；停用必须在服务端生效，不能只隐藏页面或暂停 AI 额度。
- 复用现有 AI 次数、token 与故障面板，补轻量全局异常提醒。继续保留默认 20 次及管理员热配置，不擅自引入月度金额限制、自动退款或收费供应商切换。
- 梳理隐私、反馈留存、账号数据处理和管理员权限说明，管理员不能借治理功能读取私人计划。

### 边界与验收

真实邮箱告警仅在维护者确认收件人与测试发送后启用；生产清理规则、账号注销和立即封禁策略须先确认。默认不部署 Redis、Kafka、Prometheus/Grafana 整套服务或微服务，不购买新资源。

用合成账号验证停用与恢复、令牌边界、审计和越权；用隔离文件／备份演练清理预览及失败保护。公网注册和 APK 发布仍不自动开放。

## 阶段六 稳定版与求职展示

### 目标与交付

把已实现能力整理成可复现、能解释、可展示的完整项目，而不是继续堆功能。

- 统一帮助入口、变更说明、功能对等表和当前版本索引，基于试用反馈修复小屏、键盘与辅助阅读问题；不无依据地重做所有页面。
- 提供不含真实用户数据的演示数据和 3—5 分钟演示路线，AI 演示默认使用明确标记的本地示例，真实调用由维护者自行授权。
- 补齐架构图、ER 图、核心接口与设计决策；用实际案例解释所有权、事务、409、幂等、离线队列及 AI 确认后应用。
- 给出轻量容量基线和可复现部署步骤，只报告实际硬件、数据规模、测试条件与结果，不宣称高并发商业运营。
- 完成稳定候选的三端功能核对、发布和回滚材料。只有实际决定进入大版本时才执行全面回归，不能把整个产品从头再测作为每个小阶段惯例。

是否命名为 `1.0` 及何时扩大试用另行确认。APP 备案、公安备案、公开下载和公开注册是独立发布门槛，不用开发完成替代实际确认；微信小程序仍排在核心稳定和相应前置条件满足之后。

## 暂缓与按需安排

- **AI 复盘联动**：已有 AI 新建与调整不重做。后续可在用户明确选择某周汇总及复盘并同意发送后，讨论下一周节奏，再复用现有差异预览与确认应用。是否提前取决于试用反馈，不自动扫描全账号或自动改期。
- **系统／后台提醒**：与当前站内提醒不同，需要独立设计平台权限、可靠性和时区规则；不承诺 APP 关闭后现有提醒仍会推送。
- **账号邮箱变更、旧版回收站补迁**：有实际需求再安排，分别需要验证流程和旧数据预检，不能靠直接更新邮箱或删除旧服务完成。
- **小程序、iOS/macOS、公开分享、团队协作和附件**：暂不与当前六阶段并行扩张。
- **本地小模型、个人 PC 中转、自动切换付费模型**：继续暂缓；现有手工业务、草稿编辑和外部 AI JSON 导入已提供降级路径。

## 每阶段统一执行方式

1. 开工前说明本阶段交付、范围、推荐模型与思考深度；按最新代码核对，不沿用旧文档的过期“待开发”。
2. 完成整个模块并合入相关小修复后，再集中测试新增及直接受影响业务。文档-only 更新不运行业务测试；只有明确的大版本才做全量回归。
3. 自动化优先，测试使用隔离服务或合成账号；真实 AI 调用需先约定数量，不重复付费测试。
4. 发布前保留版本、签名／哈希、真实数据备份、迁移兼容、升级数据保留和云端健康门槛。有迁移时才增加相应恢复／回退演练。
5. 原生资源或能力变化时做相关 PC／Android 验收。用户保存关闭 PC，手机连接解锁，系统安装确认由本人完成；仅服务端或文档变化不机械要求重装客户端。
6. 验收后同步适用的 Web、PC、Android 正式版本与更新源，提交 GitHub 和发布记录。Android 继续登录受限，安装包未验收不推送，自动下载默认关闭，必更另行决定。

## 模型选择说明

以上深度是本项目任务风险判断，不是额度节省比例保证。复杂的数据恢复、批量事务、同步和账号治理采用 6.1 Sol + High；简单文案或清单整理可用当前可选的 Luna + Low/Medium。纯文档与整理不必常驻最高思考深度，每阶段开始再核对实际可选模型。

OpenAI 官方指导将模型和思考深度作为任务选择，并建议用满足质量要求的较轻设置；6.1 Sol 支持 High。参考 [模型选择](https://developers.openai.com/api/docs/guides/model-selection) 与 [6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol)。这些是开发助手设置，不更换产品内的 DeepSeek 官方模型。
