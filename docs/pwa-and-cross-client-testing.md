# PWA 与跨端回归

## 能力边界

- 浏览器满足 HTTPS（或 `localhost`）时会注册 Service Worker，并可把计划平台安装为独立窗口。
- Service Worker 只缓存应用壳和同源静态资源；`/api/**` 永不写入缓存。
- 离线时可以打开已访问的应用页面；计划、任务、标签、里程碑、模板和主线的普通新增、编辑会进入当前浏览器的 IndexedDB 队列。
- 删除操作必须在线执行。当前删除接口没有携带实体基础版本，禁止离线排队可以避免误删其他设备刚更新的数据。
- 计时开始/暂停、完成、手动补录、延期和重复任务生成必须在线执行。这些操作依赖准确服务端时间，不会伪装成已完成。
- 队列不保存 Access Token 或 Refresh Token。关闭所有窗口后再次离线启动时，仍需联网恢复登录会话。
- 联网后进入“同步中心”按原顺序重试。`409 Conflict` 会保留在冲突区，不会自动覆盖服务器数据。

## 安装检查

1. 用 HTTPS 域名或 `http://localhost` 打开 Web。
2. 登录后，若浏览器支持，顶部出现“安装应用”。点击并完成浏览器安装流程。
3. 从系统应用列表启动，顶部应显示“已作为应用运行”。
4. 发布新版本后重新打开页面；出现“更新应用”时点击，确认重新加载到新版本。

## 手机回归清单

在至少一台 Android Chrome 与一台 iOS Safari（若可用）验证：

1. 宽度 360px 左右时，顶部导航可横向滚动，表单输入和按钮可以触控操作。
2. 登录、今日任务、开始/暂停/完成、补做、主线、回收站、导出分别成功。
3. 安装后的独立窗口可以登录并刷新会话。
4. 保持登录窗口打开并断网，新增或编辑一条普通计划数据，确认界面提示“操作已保存到离线队列”，顶部出现待同步数量。
5. 尝试开始计时，确认应用明确提示无法连接，而不是加入队列。
6. 恢复网络后进入“同步中心”，执行“同步等待项”，确认服务器只生成一份数据。
7. 在设备 A 离线编辑旧版本、设备 B 在线修改同一数据，再让设备 A 同步；确认操作停留在“需要处理”，不会覆盖设备 B。

## 自动检查

`verify.bat` 在前后端构建后执行 `web/scripts/check-pwa.mjs`，验证 Manifest、Service Worker、图标产物齐全，且 Service Worker 明确跳过 `/api/`。
