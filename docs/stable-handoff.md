## 日常维护与下一次改动

先核对真实状态，不直接重跑历史安装或发布脚本：

```powershell
# 在仓库根目录，只读核对源码状态及三端版本元数据
git status --short
node scripts/verify-release.mjs

# 公开健康字段，不读取账号、Key或业务内容
Invoke-RestMethod https://plan.zijun701.cn/api/health
```

随后按[发布流程](release-process.md)处理本次新增和直接受影响功能：

1. 查当时的源码、生产版本、真实5小时额度和用户操作窗口；剩余不超过10%安全保存并通知，不自行设置自动任务。
2. 业务代码变化才安排相应共享源码及隔离服务验收；原生变化才安排对应客户端。资料修订不机械重装、不重跑无关旧业务。
3. 真实生产升级前做当时的新备份、独立恢复／迁移与兼容演练，保留原数据、旧包、卷、旧服务及可执行回退。成员会话代次守卫不能绕过。
4. 签名／哈希、包身份、版本、升级保留、HTTPS健康与更新源检查通过后再发布；Android真机未通过的包不推受限源。
5. 审查敏感信息后同步GitHub源码；正式发布再建不可变标签和适当附件，不上传私测APK、真实数据库、会话、测试资料或密钥。

生产保持AI每日20次及个人热配置、已配置SMTP和经确认的运维治理；邮箱变更本版经维护者确认开启。公开注册、官网APK／二维码、自动清理继续关闭；自动下载默认关闭。资料完成不授权修改其他开关。
