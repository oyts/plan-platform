# 模型选择与额度规则

本项目按任务选模型，不永久把某聊天绑定为高强度。以下为2026年11月9日官方资料基础上的试运行起点，不是已经切换的设置，不保证固定节省比例。账户实际可用模型与思考档位优先；不可用时说明并建议替代，不猜测。

| 工作 | 起点建议 | 升级条件 |
| --- | --- | --- |
| 明确的进度摘要、归类、字段提取 | GPT-6 Luna／Medium | 多来源相互矛盾时交Sol，不让摘要模型替用户定案 |
| 例行周志与交付材料 | GPT-6 Luna／Medium或High | 长材料或需细致核验用High，事实不足先询问 |
| 总控阶段规划、跨模块拆分 | GPT-6.1 Sol／Medium | 依赖、安全或复杂取舍升High |
| 视觉稿比较、截图评审、IP文案润色 | GPT-6.1 Terra／Medium | 设定规则冲突、较长故事一致性或工程决策用Sol／High |
| 常规业务和前端实现 | GPT-6.1 Sol／Medium | 涉认证、同步、迁移、计时或疑难故障用High |
| 安全、跨端冲突、迁移和发布决策 | GPT-6.1 Sol／High | 确有复杂难点才提议更高档，不默认Max／Ultra |

## 每项任务的模型卡

开工前给用户简短说明：推荐模型及思考强度、匹配原因、任务范围、何时升级。先确认当前任务是否已有明确模型指示；有则遵从，不因本表静默替换。新聊天创建不指定模型字段时沿用应用默认，不能把本表写成已应用配置。

同一方案在代表性场景失败、范围从设计转实现、出现安全／数据风险、或长上下文导致持续返工时重新评估。先修清楚任务和证据，不一味增加思考档位。若需模型比较，只做少量有代表性的同等验收，不让多模型重复整阶段。

总控在与用户对话时，结合当前阶段、结果质量、剩余额度和返工，主动提出模型与窗口建议。无变化不重复提醒；建议须说明切换收益和代价。调整实际模型由用户本人完成，或在用户明确授权具体任务配置后用支持的任务工具执行；本次只建立建议机制，不授权任意自动切换。

## 节省用量

先读短状态和模块回执，只拉取必要来源；需要追溯才读取相应聊天。工具输出过滤为当前任务所需字段，不反复打印完整聊天、全目录素材和长测试日志。只向其他聊天发送短任务卡，不复制本聊天全部历史。

少量长期窗口保持领域上下文，短排查用临时任务。并行不是额度扩容；最多两项重型实现同时推进，设备／发布串行。文档整理不运行全量业务测试；完整阶段后集中验新增和受影响功能，UI大重构最终回归范围另立。

额度以实际300分钟窗口为准，不拿周额度或API Token价格换算5小时任务数；读不到时重试一次，再请用户提供当前百分比。新任务默认剩20%收口保存并直接通知，最新任务专属人工指示优先。无自动续做、重置券或购买；是否还有余量不是增加无关任务的理由。

生图、语音和第三方模型是独立能力和用量，不由聊天模型名称决定；新增调用须符合用户本次任务授权。聊天数增加不代表获得更多额度。

## 核对来源

- [OpenAI官方模型指南](https://learn.chatgpt.com/docs/models)：Sol用于复杂持续工作，Terra偏写作与视觉操作，Luna用于明确可重复任务；支持档位以实际客户端为准。
- [官方用量说明](https://learn.chatgpt.com/docs/pricing)：任务、上下文、模型、推理、工具与缓存影响消耗；不同聊天共享用量，不用API单价估算订阅任务数。

表中具体任务与Medium／High分配是本项目试运行建议，不是官方固定分工。后续在阶段切换或选型变化时按当时资料重新核对，不根据旧快照声称新模型已可用。
