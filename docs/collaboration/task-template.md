# 任务卡与交付回执模板

每个完整交付单元一张任务卡，避免为一个按钮或提示反复开阶段。由总控写目标与验收；执行者在自己模块回执中附结果，不修改其他模块状态。

## 任务卡

- 任务ID、创建日期、负责人角色与thread ID。
- 人工授权来源；目标、非目标、依赖及待确认事项。
- 推荐模型、思考强度、理由；实际模型由谁确认，未核对写“未核对”。
- 仓库／worktree／分支与开始提交；允许写入文件、共享文件唯一负责人。
- 验收标准和测试范围；合成／真实数据边界、系统确认与发布门槛。
- 额度停止线、终止条件；失败后保存什么，不自动重试哪些外部操作。
- 交付路径、接收角色、是否允许向谁发送简短回报。

## 执行者交付回执

- 任务ID、日期、实际完成项、改动文件与提交（没有提交明确写无）。
- 制作／编码、用户确认、测试、集成、发布分别是什么状态；不适用要明示。
- 证据路径与范围、实际失败／未测项、还需用户做什么；不把构建当真机、不把计划当成果。
- 实际模型／强度（未核对写未知），是否达到停止线，不估算虚假的调用成本。
- 未完成项、阻碍、准确续做入口；交还文件／端口／设备占用，不擅自清数据。
- 是否需要新窗口或模型调整，原因与代价；没有必要就写无需。

总控以证据核对后再标accepted。源码接受、用户采用、集成和发布是不同门槛；文档任务不要求安装或部署。周志可读已核实回执，但本人实践、AI辅助与待掌握必须分开。
