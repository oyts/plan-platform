# AI 前置基础

以下记录前置基础阶段的验收状态；后续对话与草稿生成的当前实现和发布边界见 [AI 对话与草稿生成](ai-conversations.md)。

前置阶段为 AI 对话规划准备额度账本、管理员配置、草稿协议和调用隔离边界。当时生产版本为 0.1.9，前置验收不调用收费 API，也不生成或修改真实计划。后续正式部署与原生发布以 [0.1.11 发布记录](release-0111.md) 为准。

## 管理员每日额度

管理员在“成员邀请”页面下方管理 AI 对话额度，可搜索成员、修改默认每日次数、设置个人覆盖值、恢复继承或暂停某位成员的 AI 新请求。电脑采用表格，手机采用成员卡片和底部编辑面板；管理员只能查看成员身份与额度，不读取私人计划或对话。

初始默认额度为 **0**，`AI_ENABLED=false`。个人值为 `null` 表示继承；个人值为 `0` 表示无可用次数。次数范围为 0 至 10000 的整数。修改时必须提交最新 `version`，冲突返回 409，不覆盖另一位管理员的修改。更改对下一次请求立即生效，不要求重启或更新客户端，不重置当天用量，也不取消已经接收的请求。

以 Asia/Shanghai 的自然日计次，次日零点重新计算。提高额度后剩余次数增加；降低到已用次数以下时剩余为 0。未设置月度金额上限；每日次数、单次输入/输出限制和全局并发仅限制成本规模，不能保证固定人民币账单。

| 账本状态 | 用量显示 | 结算规则 |
| --- | --- | --- |
| RESERVED | 占用 | 接收请求时原子预占 1 次 |
| SUCCEEDED | 已用 | 一条用户消息得到成功回复计 1 次 |
| RELEASED | 不占额度 | 确认未产生有效回复且可以安全退回 |
| UNKNOWN | 占用 | 超时或断连后上游结果不确定，保留占用等待核实 |

同一成员的 `operationKey` 和内容指纹只对应一条账本记录。再次请求返回原记录且 `acquired=false`；未来调用方只有在首次获得 `acquired=true` 后才允许调用模型，不能把重复 RESERVED 当作新调用。内部重试不新增扣次；更换内容复用同一键返回 409。结算保留原预占日期，即使回复跨越午夜也不扣新一天次数。客户端无预占、结算或退款接口。

Flyway V14 新增四张 AI 表，不修改现有计划结构。短事务通过一条策略行锁串行化额度准入和配置更改，外部模型等待绝不能放在该事务内。配置与审计一并提交。审计记录操作者、目标、前后额度/暂停状态和时间，不保存提示词、模型回复或 API Key。

## 接口边界

以下接口均要求登录，管理员接口另要求 ADMIN。成功读取使用 `private, no-store`，AI 与额度接口不进入离线快照或业务离线队列。

| 接口 | 当前行为 |
| --- | --- |
| GET `/api/ai/capabilities` | 返回协议版本、模型、状态、ASYNC_POLLING 和时区；`available` 始终为 false |
| GET `/api/ai/quota` | 只返回登录用户本人当天的额度、已用、占用和剩余 |
| POST `/api/ai/jobs` | 返回 503 `AI_NOT_AVAILABLE`，不预占、不扣次、不调用模型 |
| GET/PUT `/api/admin/ai/settings` | 查询或修改全局默认额度，修改须携带 version |
| GET `/api/admin/ai/users?query=&page=0&size=20` | 分页成员额度，size 最大 50，搜索最多 100 字 |
| PUT `/api/admin/ai/users/{id}` | 提交 dailyLimit（可为 null）、paused、version |
| GET `/api/admin/ai/audit?page=0&size=10` | 分页查询额度变更记录 |

即使误把 `AI_ENABLED` 设为 true，本阶段也只返回 `INTEGRATION_PENDING`，仍不提供真实对话。现有健康检查、登录和三种手动业务不依赖 DeepSeek 是否在线。

## 密钥与调用资源

使用 DeepSeek 官方固定地址 `https://api.deepseek.com` 和模型 `deepseek-flash`。截至 2026 年 10 月 15 日，官方说明该模型名对应 V4.1 Flash，见 [官方 API 说明](https://api-docs.deepseek.com/zh-cn/)。不允许客户端选择上游地址、上传自己的 Key 或让模型返回任意外部调用地址。

当前只提供适配接口 `AiProvider`，没有真实网络实现。默认资源上限为输入 8000 字符、输出 2048 token、并发 2、排队 4、总等待 60 秒。执行隔离器使用有界线程池，满载拒绝、超时取消，连续三次执行失败/超时后熔断 30 秒，不自动重复付费请求。未来 HTTP 实现还必须自身设置连接/读取超时，响应大小限制，并正确处理取消；Java 线程取消不能保证上游已经停止计费。

密钥只在服务器受限文件保存，`AI_API_KEY_FILE` 是容器内绝对路径，不是密钥内容。读取器拒绝相对路径、符号链接、异常大小和非法字符，错误不包含密钥或上游正文。健康与能力接口不会读取此文件。真实调用前还需落实主机目录权限和备份隔离；不将密钥放入前端变量、APK、EXE、日志或 Git。

本阶段无需提供 Key。下一阶段接入时，可选用 `docker-compose.ai-secrets.yml` 叠加到现有生产 Compose：

```sh
docker compose -p plan-platform \
  -f docker-compose.production.yml \
  -f docker-compose.ai-secrets.yml config --quiet
```

`AI_SECRET_HOST_FILE` 必须指向已存在的主机绝对文件路径；挂载为只读，不自动创建文件。先按实际后端容器 UID/GID 配置所有者和最小读取权限，禁止为解决权限问题而向所有用户开放读取。真实文件放在仓库和 Docker 构建上下文以外；`.ai-secrets/` 也已被 Git 忽略。基础 Compose 不引用此挂载，AI 关闭时部署不需要密钥。当前不得仅凭改开关就宣称接入完成。

## 三模式草稿协议

`AiDrafts` 校验 `schemaVersion=1`、模式、修订号、标题、阶段与最多 100 条步骤。输出必须为单个严格 JSON；拒绝未知/缺失字段、重复 JSON 字段、非整数数字、空标题、重复 ID、缺失依赖和依赖循环。标题最多 120 字、备注最多 2000 字、单项预计用时 0 至 1440 分钟。

| 模式 | 草稿限制 |
| --- | --- |
| PLAN 周期计划 | 必须有起止日期；任务日期在范围内；休息日为不重复的 1 至 7；无路线阶段或前置依赖 |
| ROUTE 目标路线 | 不要求结束日期，不绑定每日日期；可有阶段和有效的前置步骤；无周期休息日 |
| TODO 今日待办 | 每条事项指定日期；无周期范围、阶段或路线依赖 |

修改协议只允许 ADD/MODIFY，不支持批量删除；MODIFY 必须携带每个目标的基础版本。协议校验不等于业务授权：本阶段没有草稿保存、预览确认、真实写入或已有计划调整接口。

下一阶段必须在服务端补齐所有权校验、每个受影响实体的版本校验（不能只检查计划版本）、已完成/历史保护、用户明确确认以及单事务幂等应用。用户确认前，任何对话或模型输出都不得直接写真实业务。

## 下一阶段接入顺序

1. 实现服务器端 DeepSeek 适配器和持久化异步任务。提交立即返回任务 ID，客户端短轮询取结果，避免超过现有原生请求超时。任务按账号隔离，不把付费调用当作普通离线重放。
2. 建立对话、模式建议和草稿修订，限制上下文长度；发送前说明第三方处理范围，只传当前用户明确提供或授权的必要数据。补充对话删除、保留期限和过期账本的幂等保留策略，不无限保留原文。
3. 建立预览、手工调整、二次 AI 修改和明确确认应用；以三个模式的新增流程先试点，再实现已有计划节奏调整和冲突处理。
4. 上游异常时保留当前草稿，允许稍后重试、手工编辑或导入外部 AI 结果；不自动切到另一收费服务。暂不部署个人 PC 中转或客户端小模型，不把它们作为可用性承诺。
5. 在隔离 MySQL 8.4 数据库验证 V14、额度并发与恢复，完成受影响测试后再发布新版本；原生包必须使用新版本号，不能重打已发布的 0.1.9。

只验证新增和受影响功能，不重跑无关业务。本地 H2 执行 V1 至 V14 成功；后端验证管理员授权、用户隔离、热生效、409、次数不重置、预占去重、并发不超额、未知结果保留占用和上海午夜归属。前端验证表单边界、离线禁用、继承/个人额度、暂停/恢复、搜索、冲突和 320/390/430/844 宽度；原邀请流程同步回归。
