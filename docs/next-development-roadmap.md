# 计划舱下一轮阶段开发规划

规划日期：2026年10月19日。以已发布的Web、Windows、Android 0.1.15（Android构建20）为基线，整合维护者的《计划舱待开发列表》和本聊天的后续建议。本轮目标是让AI规划更容易使用、日常任务能得到适当提醒、复盘能够指导后续节奏，并补齐邮件和运行保障。

下列内容保留规划范围，完成状态以本页最新执行状态为准；规划本身不授权修改生产配置、发真实邮件、调用付费AI或开启公开注册。桌面原稿保留不变；本文是下一轮统一入口。上一轮六阶段的实际结果见 [0.1.15发布记录](release-0115.md) 和 [续做记录](roadmap-progress.md)。

当前执行状态：第一阶段以0.1.16／Android21交付；第二阶段已以0.1.17／Android22完成生产、正式双端定向验收和下载／受限更新源发布，见 [0.1.17发布记录](release-0117.md)。既有邮件告警保留；公众注册、官网APK、自动清理仍关闭。功能与精确边界见[AI工作台](ai-workbench.md)和[续做记录](ai-workbench-progress.md)；第三至六阶段尚未开工。

## 阶段一 邮件安全与运行保障

### 邮件与账号交付

- 取消邀请邮件向管理员抄送，删除相应副本文案。邀请、验证和密码找回邮件只发给对应用户；管理员仍能查看不含完整敏感链接的投递状态。
- 在账号页显示已验证或未验证，提供主动发送、重新发送和打开验证结果的完整流程。
- 验证重发增加冷却和服务端限流；SMTP失败、链接过期、已使用和重复点击有清楚结果，不静默宣称成功。
- 保持公开注册关闭、管理员邀请注册开启。开启邮箱验证不等于强制限制未验证用户；若要增加业务访问门槛，必须另行确认策略。
- 存量用户可以继续登录并补验，不批量伪造已验证状态，不突然阻断管理员、原计划或找回密码。现有邀请和新验证链接的身份凭据不得记录到日志或抄送第三人。

### 运行保障交付

- 把真实MySQL备份、OSS下载哈希核对、独立恢复演练和磁盘元数据接入既有管理页；未知和过期不能显示为健康。
- 补充故障去重与恢复邮件，先确认收件人和测试接收，再启用实际发送；不把现有SMTP可用当成告警已启用。
- 明确成员停用、恢复、令牌撤销与离线边界，确认后再启用生产治理。管理员不因此获得读取私人计划的权限。
- 保留清理预览和审计，不新增未经授权的自动删除，不清理唯一恢复点、旧发布或签名材料。

### 集中验收

使用合成账号验证无CC、验证令牌一次性、过期与重发限流、存量登录兼容及邀请仍受控；用隔离证据验证备份过期、未知、故障去重和恢复通知。真实邮件仅在明确确认后发送。治理启用后保留会话代次及回退守卫。

## 阶段二 AI规划工作台与手机输入体验

### 草稿箱和恢复

- 把“最近对话”整理为清楚的会话与草稿入口，区分未完成草稿、已应用结果和处理中任务。
- 自动保留未发送文字、手改草稿和外部JSON输入；显示“已存本机”“已保存云端”“保存失败”，提供明确的保存与继续编辑入口。
- 本机输入按账号和服务器隔离，切换页面、刷新、异常重开后可恢复。服务器版本已改变时保留本机修改并引导比较，不静默覆盖其他端。
- 本机自动保存不自动调用AI、不扣次数、不生成真实计划，也不自动重放付费请求。恢复时不恢复“确认生成”勾选或自动发送状态。
- 明确区分清空输入、删除选中草稿与清空草稿箱；操作须显示范围并确认，不删除已生成计划、历史、同步队列或额度记录。清空后取消待执行的自动保存，防止内容重新出现。
- 处理中会话不能删除；批量清空须列出未删除项，不一律显示成功。清空不取消或重放已经接收的AI任务，任务完成后仍可核对结果。
- 用户明确保存的规划草稿不应随临时会话过期静默消失；实施时明确其独立保留规则、容量上限及结构化导出路径，不承诺无限聊天记录永久保存。
- 原会话过期后，独立草稿仍可查看、编辑和导出，但不能复活过期会话或旧请求键。继续AI须新建会话并主动发送；旧调整草稿须重新载入最新对象、校验版本与历史保护，再预览确认，不能绕过最新快照。

### 对话布局和模式选择

- 电脑以对话和草稿并列展示；手机使用“对话／草稿”切换或独立面板。对话采用有界滚动，输入区稳定可达，长草稿按阶段折叠和分页。
- 处理软键盘、安全区、返回键、滚动位置和未保存提示，避免聊天增长后主要按钮远离用户。
- 通用入口默认“让AI推荐”，允许先用大白话沟通。从某种模式的新建入口进入时保留其明确选择，并允许新建场景下主动切换。
- 推荐后提供三模式的结构示意和适用理由，用户确认后才生成完整草稿。不为每次推荐默认发起三次完整付费生成；静态示意必须明确标记，不能伪装成真实AI结果。
- 已有对象调整保持原对象类型，不把周期计划直接转换为路线或待办。新建草稿改模式前保留原草稿并确认后续处理。

### 路线时间参考和配色

- 复用每步骤已有的参考分钟，AI依据用户可投入时间、基础和范围提出估算，用户可修改。
- 阶段与整条路线汇总所属步骤的参考投入；汇总不随当前分页、搜索或“仅未完成”筛选错误变化，区分总投入与剩余投入。
- 不把参考投入等同日历期限；没有每周可投入时间时，不编造“几周必能学会”。目标路线继续允许长期、间歇推进。
- 新增三端共享的颜色选择组件，支持RGB三个0至255整数、HEX双向输入、预览和常用色，保留兼容HEX存储。覆盖计划、标签、路线新建与编辑，不仅改一处页面。

### 集中验收

验证自动保留与重开、账号／服务器切换、存储失败、并发409、清空竞态、长对话与键盘、模式可选和确认、完整阶段时长汇总、RGB边界及三端一致。不重复付费验证旧AI接入。

## 阶段三 系统通知与事项提醒

### 用户可分别设置的提醒

| 提醒 | 预设时间或规则 | 独立控制 |
| --- | --- | --- |
| 周期任务提前提醒 | 默认提前5分钟，用户可改为3分钟或其他合法时长 | 单独开关和提前量 |
| 到点开始提醒 | 到计划开始时间，应用记录仍未开始且未完成 | 与提前提醒分开开关 |
| 今日待办收尾 | 每天22:30，仅有当天未完成待办时提醒 | 单独开关和每日时间 |

上述默认是配置预设值，不表示升级后自动启用通知。既有用户不被静默打开新系统通知；首次主动开启时才申请系统权限。Web保留站内提醒和同一账号配置，不承诺关闭浏览器后也有相同后台能力。

### 时间和状态规则

- 有明确开始时间的周期任务才产生分钟级提醒。无开始时间的任务不随意补时间；今日待办仍按日期收尾，不强制新增每日具体开始时间。
- 明确补做日期、休息日、跨午夜、时区和修改开始时间后的重新安排。休息日不会删除真实任务；已有明确安排的任务依据实际记录判断。
- “尚未开始”不能只看当前计时开始字段，因为暂停可能清空它；依据稳定的首次开始记录或等价业务证据判断。已开始、暂停、完成、跳过、删除、归档的事项不误发未开始提醒。
- 文案为“到计划开始时间了，是否开始？”，不声称知道用户现实中是否已经阅读或练习。
- 改期、完成或关闭提醒后取消／替换相关通知；退出账号或切换服务器时清理对应的通知安排，不泄露上一账号内容。
- 默认每个设备需本人开启，可设置主提醒设备；同一设备同一事件防重。不承诺断网多设备能实时互相取消。
- 发出条件提醒前核对可用的最新状态；数据不新鲜且无法核实时，不发带“仍未完成”断言的通知，回到应用后提示核对，避免伪造实时检测结果。
- 提供免打扰、锁屏隐藏事项正文和通知跳转；默认不在通知内直接完成任务，避免引入绕过版本校验的写入。

### 原生交付门槛

先验证Windows现有安装身份下的系统通知与计划投递、Android通知权限与时间调度，再实现完整业务。两端应明确区分前台、普通后台、正常关闭、设备重启、关机及被系统强行停止时的行为；不使用持续占用的定时循环承诺微信式必达。

Android精确时间受权限和节电策略影响；Windows计划通知也有设备关闭后的丢弃条件。技术方案须基于实际项目版本验证，不能直接照搬其他版本插件。参考 [Android闹钟与提醒](https://developer.android.com/develop/background-work/services/alarms) 和 [Windows计划通知](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/app-notifications-scheduled)。

首版优先本机调度，不引入付费推送平台。若实际需求必须覆盖长时间离线、系统强停或多设备实时变化，另行评估服务端推送和国内设备渠道；不把本机提醒宣称为完整远程推送系统。

### 集中验收

验证独立开关、提前量、9:30任务在9:25／9:30的两类事件、完成后抑制、所有待办完成不提醒、改期撤销、同事件去重、权限拒绝／撤销、重开与重启、过期状态、通知跳转和账号退出。系统授权由用户处理；必须有真实Windows和Android通知证据。

## 阶段四 日周复盘与AI节奏调优

### 事实汇总和引导

- 新增三模式统一日汇总，复用现有周统计。周期计划、今日待办与目标路线分别展示，不将没有每日配额的目标路线算成“今日未完成”。
- 完成和未完成列表来自实际业务记录，不再要求重复手填；用户仍可写收获、阻塞和感受。旧手填日复盘保留，不用自动内容覆盖个人记录。
- 明确安排日期、实际完成日期、计时流水和跨日口径；没有完成时间的旧数据标注未知，不推测回填。显示汇总时间与只含已同步数据的边界。
- 增加可选的精力／负担自述，不根据完成率推断心理或身体状态。
- 当天确实有适用事项且首次全部完成时，给一次轻量日复盘引导；空任务日不按0/0视为全部完成，后来重开任务不反复打断。
- 日复盘定时预设22:30；周复盘预设周日22:30。日期、时间和开关均可调整；已完成对应复盘则取消当期引导。
- 待办收尾、日复盘和周复盘的开关独立，但同一时刻合并展示或排队去重，避免22:30连续三条通知。

### AI分析和周调整

- 用户选择本次日／周汇总、复盘文字及相关规划，预览并同意后主动请求AI分析，沿用每日额度；不在后台自动发送或扣次数。
- 日复盘AI提供事实总结、鼓励和可执行的反思建议，不从日分析入口发起节奏批量修改。
- 周复盘AI先总结，再在用户询问或达到持续趋势条件时提供可选调整。初步建议至少有两周有效记录再主动提示趋势，确切门槛在实施时确认；单日失误或单周异常不触发大幅改动。
- 完成率良好不等于有余力；增量还要用户明确表达有精力。完成率下降先询问阻塞和负担，允许用户拒绝建议或暂不提醒，不使用责备文案。
- 提供建议冷却和上一轮调整回顾，避免每周反复重排。新增练习、每日减量、延长周期分别列影响，目标路线以投入节奏／步骤粒度调整，不强加日期。
- 周复盘发起的节奏调整必须再次明确确认，复用逐项差异、所有权、版本409、防重、原子提交和执行历史保护，不删掉重建整套计划。
- “周复盘后才建议调整”限制的是复盘自动推荐入口，不撤销用户日常手工修改或主动进入既有AI调整的能力。

### 集中验收

验证三模式口径、无数据与旧完成时间、日复盘兼容、提醒抑制与合并、AI同意范围、日分析不改计划、周趋势门槛与拒绝、未知调用不重试、草稿恢复、409和批量原子性。新复盘数据进入相应缓存、导出、私有备份与恢复版本，不能只改页面漏掉数据中心。

## 阶段五 个人整套模板库

- 复用已有周期计划／目标路线结构复制，补命名、分类、收藏、预览及版本明确的个人模板管理，不再写第二套复制逻辑。
- 支持保存本人现有结构或AI规划草稿；不自动保存整段AI原文、私人复盘、账号信息或执行历史。
- 从模板建立新对象时重新选名称、周期和休息日；保留阶段与依赖映射，不复制完成状态、实际计时、通知授权或本机队列。
- 模板修改不改变已经创建的计划，应用模板先预览再确认，重复提交防重，其他用户不可读取。
- 首版不做公共市场、公开分享、跨账号协作和模板付费。相关模板数据纳入私有备份／恢复，遵守格式版本和所有权规则。

集中验证完整结构、关系重映射、历史不复制、修改互不影响、越权、防重和备份兼容。

## 阶段六 试用收口与稳定候选

## 统一开发和发布规则

1. 每阶段开工前确认交付范围、推荐模型和思考深度，核对最新源码，不擅自切换模型。复杂事务、账号安全、原生调度及AI修改以正确性优先，简单整理不默认占用最高深度。
2. 整个阶段开发完成后，集中测试新增及直接受影响功能；不逐个小提示反复发包，不重跑无关旧业务。维护 `scripts/release-test-scope.json`。
3. 自动化优先，使用合成账号和隔离服务。真实AI请求先约定上限，保留现有默认20次／天与管理员热修改，不新增未经确认的预算或自动付费切换；通知权限、系统安装提示、真实邮件接收和生产安全决策仍由用户参与。
4. 原生包变化时安排对应PC／Android验收；仅后端配置或文档变化不机械重装。三端共用业务及数据规则，不要求Web复制操作系统后台能力。
5. 发布保留版本、签名／哈希、迁移兼容、备份、升级保留与云端健康门槛。已完成内容不得用旧证据冒充本次新功能验收；不删除旧数据、包、卷和回退材料。
6. 每个实际发布版本同步GitHub源码、发布记录及适用的正式更新源；未真机验收APK不推送。官网APK／二维码和公开注册保持关闭，自动下载默认关闭，必更另行确认。
7. 继续检查真实5小时额度。剩余不超过5%时安全保存代码、证据及准确续做说明，直接通知用户并等待，不自行安排定时续做。自动任务保持暂停，只有用户明确要求才重新开启。
