# 运行证据与成员治理

此模块随0.1.15部署，0.1.16已在维护者确认后启用生产运维与成员治理。管理员确认收到本轮测试邮件后，持久去重告警邮件也已启用；实际发布与验收见 [0.1.16发布记录](release-0116.md)。入口为管理员的“运行与治理”；普通成员没有管理权限。它不提供查看成员私人计划、AI原文或备份正文的能力。

## 状态不是健康承诺

后端默认 `OPERATIONS_ENABLED=false`、`MEMBER_GOVERNANCE_ENABLED=false`，采集文件未配置。未知、过期、读取失败和超出采集上限都明确标记为未知，不显示为正常。

运行页面展示本地MySQL备份新鲜度、OSS下载后SHA-256核对证据、最近30天独立恢复演练证据、主机备份目录所在磁盘，以及固定分类的操作失败。同一未恢复故障复用事件编号；恢复后关闭事件，再次发生生成新事件。管理员可手动核对，启用的服务每五分钟核对一次。0.1.16已在真实管理员测试收信后启用持久告警；生产未人为制造故障，故障／恢复投递逻辑以隔离验收为准，不能把SMTP测试邮件当作真实故障邮件已投递的证明。

## 采集与权限

`scripts/operations-status.py` 是有界、只读业务数据的宿主机采集器。它不连接数据库，不上传备份，不删除文件，也不发送邮件。仅处理受管 MySQL 备份命名和 SHA-256 旁文件；单轮最多 200 个文件、64 MiB 压缩读取和 256 MiB 解压验证。超出限制保留未知状态，不能据此建议删除。

生产已确认并保留原恢复点目录，使用独立的 `operations` 元数据目录，宿主机写入者为可信维护者；后端UID100/GID101，目录2750、采集文件0640。后端只读挂载整个目录，`OPERATIONS_STATUS_FILE` 指向其中的 `status.json`。不要单独挂载原子替换的文件，否则容器可能一直读取旧inode。目录内不得存放Key、数据库口令或业务备份正文。

`configure-operations-runtime.py`保留原夜间备份任务，补入5分钟有界采集。日常备份沿用同一受管目录，报告备份／OSS失败，并在实际上传后下载核对最新备份。现有恢复演练对应的恢复点继续保留。脚本和原crontab备份存于服务器受限目录，不执行清理，不创建Codex续做任务。告警邮件启用工具先做无写入预检，必须显式确认已收到管理员测试邮件；失败恢复原关闭配置。

以下是部署准备示例，绝对路径须先核实，不代表生产定时器已配置：

```sh
python3 scripts/operations-status.py collect \
  --backup-directory /absolute/verified/mysql-backups \
  --output /absolute/private/operations/status.json \
  --drill-evidence /absolute/private/operations/drill.json \
  --failure-evidence /absolute/private/operations/failures.json \
  --group-readable
```

只有显式添加 `--verify-oss` 才会通过既有ECS RAM角色下载最新已校验备份及其旁文件，与本地SHA-256比较。5分钟采集默认不联网；日常备份成功上传后执行真实下载核对。本次生产演练和升级后日常备份链路均实际完成OSS往返验证。

`mysql-restore-drill.sh` 仅在独立恢复并完成全表校验后，才按可选的 `PLAN_OPERATIONS_DIRECTORY` 写演练元数据。`record-drill` 自身只验证指定文件的完整性，**不能单独证明数据库已恢复**；不能为消除告警而手工伪造成功。`record-result` 仅记录 BACKUP_FAILED、OSS_FAILED、RESTORE_FAILED 三类布尔结果，命令输出不包含私有异常正文。

## 清理只有预览

管理员可以调整最近保留份数、保留天数、备份时限和磁盘阈值。版本冲突返回 409；数字规则的修改前后值记录审计。页面展示建议，服务没有执行删除的接口。

清单不全、没有近期独立恢复证据、没有 OSS 下载核对证据时，所有文件保留。最近 N 份、至少两份已校验备份、OSS 和恢复演练对应的恢复点、未校验文件都受保护。预览不涉及旧发布、签名密钥、数据库卷或其他目录。真实清理仍须另行授权，不能把预览当成清理任务。

## 成员停用、恢复与回退底线

治理开关关闭时不能修改成员状态。启用须先由维护者确认策略；不会因本次开发自动启用。仅可管理普通成员，不能在此停用自己或其他管理员。每次变更需要原因、明确确认和最新版本；审计只包含操作人、目标编号、原因、动作和时间。

启用后的停用在下一次联网 API 请求生效，同时撤销刷新会话并推进账号会话代次。恢复不复活旧访问令牌或刷新令牌，用户需要重新登录；账号和原有计划不删除。登录、刷新和治理使用一致的账号锁顺序，防止并发请求重新签发被撤销的凭据。

已缓存的离线身份仍遵循原有 24 小时边界，不宣称可以远程抹除断网设备。一旦账号发生过治理，关闭开关也不取消会话代次校验。

**发生过治理后，不能直接回退到不识别会话代次的旧服务**，否则可能重新接受旧访问令牌。部署或回退前运行只读守卫：

```sh
python3 scripts/check-governance-rollback.py --target-supports-generation no
```

该命令发现治理过的账号会拒绝不安全回退。只有已核实目标代码保留代次校验时，才可指定 `yes`。不能为了回退清零代次、删除审计或恢复旧真实数据库覆盖新业务。当前正式治理已启用，0.1.15仍保留代次校验；不可照搬面向更早镜像的回退命令。
