## 2. 信息架构与导航

主导航始终清楚显示“周期计划／目标路线／今日待办”三模式。模式内各自保留位置、统计、历史与回收站语义；公共工具以次级导航进入，返回时保留原模式及选中对象。已有冷启动只承诺记忆工作区，不扩大为自动恢复任意工具页。

PC建议“模式入口＋模式内侧栏＋内容区”；窄屏建议“顶部模式切换＋当前模式的少量常用入口＋更多工具”。这是布局提案，不引入新URL或全局搜索。当前模式、页面标题、选中对象和主动作使用文字表达，不能只靠红蓝颜色区分。

| 导航组 | 现有路由 | 重构要求 |
| --- | --- | --- |
| 周期计划 | `/schedule`、`/plans`、`/plans/:id`、`/plans/:id/studio`、`/stats`、`/reviews`、`/records` | 先见当前计划与当天执行，再进入编辑、统计、复盘和历史；保留自选休息日及任务／进度双版本 |
| 目标路线 | `/routes`、`/mainlines`、`/route-progress`、`/route-records` | 路线、阶段／步骤和依赖关系可辨；自由／顺序执行、暂停／归档／删除分开，不强加截止日期或日更 |
| 今日待办 | `/todos` | 当日／历史、查询、完成状态和分页在本模式内处理，不混入周期统计 |
| 个人工具：规划与回顾 | `/ai`、`/overview`、`/reminders`、`/weekly-review`、`/reflection`、`/organize`、`/templates` | 显示所作用的模式和对象；AI不自动调用，预览不等于应用 |

## 3. 高频路径与优先级

优先级用于设计和集成顺序；整个UI交付单元完成后集中验收，不把每个小调整拆成发布阶段。

| 优先级／任务 | 建议路径 | 完成判据 |
| --- | --- | --- |
| P0 当天执行 | 记忆的周期工作区→今日任务→原有开始／暂停／完成操作 | 当前计划、日期、状态、计时和主动作同屏可辨；已完成历史不能被编辑捷径改写 |
| P0 推进目标 | 目标路线→所选路线→阶段／步骤→原有执行动作 | 看得见可做项与阻塞原因；无期限路线可正常使用；暂停和删除不混淆 |
| P0 记录零散事项 | 今日待办→新增或勾选→原位反馈 | 常用操作保持页面上下文，长列表可分页；陈旧勾选失败恢复原值 |
| P0 离线与冲突 | 当前页待同步提示→同步／冲突中心→手动处理→返回原对象 | “已存本机／待上传／冲突”分开；不自动提交、清队列或丢后续操作 |
| P1 AI辅助 | 当前模式／对象→AI工作台→同意必要外发→完整预览→明确应用 | 保留旧会话、草稿、保护项、分批结果与后续队列；UNKNOWN不自动重试 |
| P1 往周复盘 | 周复盘→所选历史周→编辑→刷新／离线再开 | 日期深链和本地文字保留；取消换周保留原周和输入；原生延后认证不跳走 |
| P1 数据与账号 | 个人工具→数据／安全→预检或确认→系统交接结果 | 恢复创建新记录，不覆盖旧记录；导出、分享、安装的取消和失败有明确结果 |

建议验收目标：进入任一模式后，最常用主动作无需先打开“更多”；工具返回不重置模式。它们是待验证的设计目标，不是当前交互测量结果。

## 4. 主题、组件与首次体验

建议视觉方向为清晰的工具界面：浅暖中性底色、清楚的文本层级、克制的红蓝强调色。星下同路主题增加装饰与氛围，数据、表单和状态仍保持同一阅读规则。具体色值、字号、间距和断点留在批准后的设计规格中，先使用现有系统字体，不安装字体或引入新依赖。

- 首次可交互进入工作区时提供轻量主题选择：“简约／星下同路”，附“稍后，使用简约”。不在验证链接、必更安全出口或关键恢复流程中拦截。记住选择，后续从设置修改，不在每次启动重复询问。
- 主题与“显示IP”是两个独立偏好；“简约＋IP开”和“星下同路＋IP关”均成立。首次建议IP默认关闭，由用户主动开启；不把选择IP主题视为批准整包素材。
- 偏好建议先在本机按服务器与账号作用域保存；匿名选择仅作本机暂存，不自动跨账号沿用。退出或切换账号不带入另一账号的私有状态；跨端云同步另列新增需求。新增展示偏好不能改名、覆盖或清除现有业务缓存键。
- 主题只改变展示，不更换模式、不改业务数据。IP关闭或素材不可用时，所有功能完整可用。明暗模式如已有则保留；新加明暗方案先计入设计范围，不能默认将其当成已实现能力。
- 组件分四层：展示令牌（色彩／字体／间距／层级）、基础控件（按钮／输入／选择／对话框）、业务外观（任务行／阶段依赖／计时／分页／差异预览）、完整页面状态。业务校验和权限仍归原领域逻辑。
- 主动作、危险动作、只读历史、待同步与冲突使用固定语义，不随角色主题改变含义；状态同时有文字／图标，不能只换颜色。空状态解释真实模式和第一步，不填假任务或假统计。
- 键盘焦点、触摸命中区域、屏幕阅读顺序、缩放、大字体、减少动态效果、长名称和横竖屏作为组件规格；窄屏通过重排和折叠次要信息解决，不隐藏关键操作。

## 5. IP接入层与采用边界

应用内先提供固定预留区：PC可用内容之外的侧区，窄屏放在不影响主动作的折叠区域。表单、冲突比较、账号认证、系统确认和键盘弹出时优先让出空间；不采用覆盖按钮、挡住列表、拖拽漂浮或自动弹出的角色层。角色隐藏后不留下空洞或无法关闭的入口。

只规划静态资源槽位、别名、可访问文字和素材缺失回退；此轮不复制、裁改、公开上传素材。后续采用清单逐项记录“索引别名／来源哈希／允许用途／裁切或派生授权／采用状态”，由IP确认语义、UI负责布局、code审核产品集成。未采用时只用带文字的结构占位，核心UI可先继续。

- 棠露与澄翎是两位独立人物、两真实非人本体；共同化形须两位一起，同刻一具共同人形。不得画成两位各自独立完整人形同时活动；共同人形的一种主导态可与另一位独立本体同场。Q是独立二头身表现，不称为真实本体。
- 正常／Q、主导态／另一位本体若需在界面展示，应标明表现语境；不把`FULL_PAIR`当作同刻双人形依据。故事A暂用与命名C选择分开，不恢复旧羊狼或已撤独自完整人形方案。
- 分域沿用当前索引：`BLUE_NATIVE`管蓝本体整体和尾形，`M0_FRONT`管同一心形前脸；`NORMAL_RATIO`／`Q_RATIO`只管比例；`ACT_*`只借表演语义。工作稿不是整包已批准素材，旧图不能覆盖当前分域权威。
- UI可预留角色署名和短文位置；实际对白采用要核对原语境，不把角色文案当作业务成功提示或AI实时理解。无手本体不接纸持笔，不新增读心、用户供能或强制牺牲设定。
- IP整包最终采用由用户审阅；接入某个明确获准素材不等于全部RC1新细部与统一册已批准。软件集成、动画和实际配音分别记录，不能借静态展示顺带启用陪伴规则。

## 6. 必须保留的状态、数据与深链

| 状态组 | 设计与未来验收要求 |
| --- | --- |
| `empty`／`loading`／`error` | 空、未采集和零区分；加载和错误保留输入；换账号／服务器／对象后忽略陈旧读取；不把所有401／404／格式错误都称作TLS故障 |
| `offline-cached` | 显示缓存范围与年龄；最近身份有效边界为24小时；缺快照不显示为空成功，过期内容不能借视觉入口编辑 |

| `conflict409` | 保留本地草稿和后续操作；仅展示实际存在的基础／本机／云端版本，手动确认；无共同基础不称三方合并 |

| `readonly-protected` | 计时、完成历史、双版本、归档／暂停／删除、对象所有权和服务端依赖校验不因新控件失效 |

## 7. PC／Web／Android差异

| 平台 | 布局与输入 | 平台能力和未来验收边界 |
| --- | --- | --- |
| Windows PC | 宽屏侧栏、键盘焦点、鼠标与缩放；长表单和差异比较保留可见操作 | Tauri请求、Credential Manager、原生保存／通知／更新；系统文件窗口可能需本人选路径；更新签名不称为新增Authenticode认证 |
| Web（含手机浏览器） | 依视口重排；history URL刷新与直达可用；不把手机网页等同Android应用 | 应用壳SW与私有快照分开；无安装身份或浏览器关闭后的提醒保证；个人缓存按账号／服务器隔离 |
| Android原生 | 触摸、软键盘、安全区、系统返回、横竖屏与大字体；主动作不被IP或底部区域遮挡 | Java请求、Keystore、受限APK源、系统安装／分享／文件权限及厂商后台限制；取消权限不误报成功，不开启公共APK |

全端维持同一信息和状态语义，不要求系统交接界面完全相同。原生安全会话保护不等于本机业务缓存已成为加密数据库；系统提醒可达性也不作跨平台绝对保证。
