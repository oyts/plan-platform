# 小规模只读性能基线

2026 年 10 月 18 日对 0.1.15 候选进行了有界测量。它用于识别小服务器上的明显延迟与资源问题，**不是公网容量、并发用户数或商用 SLA**。测试没有访问生产业务库，没有付费 AI 调用或真实邮件。

2026年10月22日资料核对说明：当前正式版本已为0.1.19，但本页仍是0.1.15的历史测量，不代表0.1.19的性能结果。本次只修正文档一致性，没有重跑负载或生成新数字；当前发布证据见[交付索引](stable-handoff.md)。

## 实际条件

- ECS：2 个逻辑 CPU，Intel Xeon Platinum，系统可见内存 1870 MiB；共享主机上保留正式服务及 MySQL 8.4。
- 候选容器：限制 0.6 CPU、480 MiB，Java 堆 192 MiB；只绑定回环 43145，没有公网暴露。没有 Redis 或预热缓存服务。
- 数据库为独立合成 schema，整库 2 个用户、2 个计划、2 条计划任务、2 条路线、4 个步骤和 2 条待办；请求只读取其中一名普通用户的数据。该规模不足以证明长列表或大数据量性能。
- 每个接口预热 3 次；并发分别为 1 与 2，每组 15 个请求，每次响应后人为等待 50ms。总计 9 次预热、90 次正式测量，单次超时 15 秒。
- 本机回环 HTTP，不含公网链路、TLS、登录 BCrypt、浏览器渲染、写事务、备份导出或第三方模型延迟。

分位数使用 nearest-rank；每组只有 15 个样本，因此 p95 就是该组最大值，不能视为稳定的尾延迟估计。带人为间隔的观察吞吐为约 7—17 次／秒，不是最大 QPS。结束时一次容器快照为 292.9 MiB／480 MiB、33 个进程／线程计数；它不是峰值内存或持续 CPU 统计。

读取前后 37 张合成表校验和完全一致；实际公网健康和公开注册关闭状态不变。候选容器已停止，独立数据库与证据保留。最终 JAR SHA-256 为 `6a68b763d7b05c48aaaae379eb7ba9eb313840ab28e79b4b3333039823690013`，与部署包、独立原生构建清单绑定的 API 一致。早先另一个打包前 JAR 的测量记录保留，但这里仅引用最终文件结果。

## 复现方式

工具为 `scripts/roadmap-performance.py`，只接受受管 `roadmap-candidates` 中的独立目录及 `plan_acceptance_` 合成数据库。先上传当前 JAR、该脚本和公共验收辅助脚本，使用一个全新的 0700 目录；它以排他标记防止整轮误重跑，私有夹具只在服务器内部读取，不打印凭据。

```sh
python3 /home/oyts/plan-platform/roadmap-candidates/新的独立目录/roadmap-performance.py \
  --directory /home/oyts/plan-platform/roadmap-candidates/新的独立目录 \
  --state-directory /home/oyts/plan-platform/roadmap-candidates/已验收的合成治理夹具目录
```

不要在现有目录重新执行、改变数据库名为生产库，或提高并发来“刷分”。现有最终报告位于服务器 `roadmap-candidates/20261018-1555-final/report.json`，本机脱敏副本在被 Git 忽略的 `acceptance-results/roadmap-stable-pc/final-mysql-baseline.json`。如要评估更多用户，应另行约定合成数据规模、资源隔离、运行时间和停止阈值。
