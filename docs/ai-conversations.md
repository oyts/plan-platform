# AI 对话与草稿生成

AI新建规划支持通过对话选择模式、生成及多次修改草稿，用户预览确认后，一次性创建周期计划、目标路线或今日待办；也可明确选择已有对象并预览调整差异后原地修改。Web、Windows、Android共用业务源码，最新候选／生产API为0.1.22、Android构建27，官网APK和二维码继续关闭。线上默认额度为每人每天20次，管理员的默认额度、个人覆盖和暂停控制继续保留。实际分发边界见[0.1.22记录](release-0122.md)；以下2026年10月16日样本是历史验收，不代表后续版本新功能已测。

## 核心阶段2：完整大纲和外部协作

长规划可先生成完整大纲，核对覆盖范围后分批细化，每批最多10项，发送、手动补齐和最终应用都由用户明确操作；未全部完成不能整体改写或应用。预算和批次跨重开保留，不能通过重建相同工作流重置预算。选中草稿可准备不含账号／业务ID／服务器地址的协作包，交给用户选择的外部AI；导回先只读差异，再确认保存草稿，应用真实业务仍另行确认。独立副本不携带旧对象修改权限，陈旧绑定返回409。容量、过期、失败及真机证据见[阶段2记录](ai-long-planning-progress.md)。

## 核心阶段1（0.1.21已发布）

0.1.21／V31将交流、生成和修订意图分开，保留独立需求笔记，新增每次尝试的脱敏诊断及可选的一次有界修复，正式环境已按批准启用。旧客户端省略意图时继续AUTO，未知结果不自动再调，手动业务和草稿预览仍独立可用。修复共享父请求的Token／时间及预占，不多扣一次用户对话次数。详见[实际进度与预算](ai-reliability-progress.md)和[正式发布](release-0121.md)。下文2026年10月16日样本是历史证据，不代表新版本重新执行收费验收。

候选协议增量：`POST /api/ai/sessions/{id}/jobs`可带`intent=DIALOGUE|GENERATE|REVISE`，省略仍兼容AUTO；模式确认、所有权、version和operationKey仍必需。`PUT /api/ai/sessions/{id}/requirements`传`text`与当前`version`，只保存笔记，不预占额度或改动手改草稿；陈旧版本409。本人读取会话时可见requirementsText及每轮diagnostic.details，包含尝试序号、状态／原因、字符数、已知Token与耗时，不包含密钥或上游原始响应。成功尝试reason可为null，以state=ACCEPTED表示成功，不能将null当未知用量或失败。管理员原因统计也不包含对话正文。

代码的修复开关默认关闭，0.1.21生产环境已按批准显式启用。最多一次额外修复，父请求两次共享总期限、总输出预算和保守输入字节边界；结果未知、超时、模式不符或用量缺失不自动再调。需求笔记保存按钮在手机展开时不再被悬浮输入区覆盖。10月24日独立Android五组、最终Web六项、Windows完整业务及重建后的保留补验通过；最后一次PC原对话由维护者打开后只读核对，独立证据和后续正式升级证据分别记录，不互相冒充。

## 用户操作

“AI 规划”位于电脑导航和手机“更多”菜单，三种业务的新建位置也分别提供 AI 构建入口。直接进入时可以先让 AI 推荐模式；从具体模式进入时表示用户已经选择该模式。

第一次发送前必须同意将本次对话与草稿交由 DeepSeek 处理。新建服务只发送当前对话、最近的必要上下文和当前草稿；已有对象调整还需单独同意载入所选内容，不扫描其他私人计划，不自动附带账号密码或服务器 API Key。用户输入的对话也会发送，必须避免自行粘贴敏感资料，不能将提示说明当作自动脱敏保证。

AI推荐不会自动切换模式。尚未选择模式时，只能讨论和推荐，不能提交草稿。选择后可反复交流；“发送并讨论”只交流，不更新草稿，“生成／修改草稿”才请求完整草稿。修订须保留未要求修改的内容，仍需用户核对。模型输出必须通过服务端校验；无效输出不替换已有草稿。

用户可编辑规划名称、任务标题、说明、日期、预计用时、周期休息日、路线阶段名称、步骤所属阶段和前置依赖，也可在草稿里增删步骤。每组显示 10 项，最多 100 项。未保存修改时，不能继续 AI 修改或确认生成；刷新、切换及离开页面会提示未保存内容。模型输出不是事实保证，具体内容和时间安排仍需用户核对。

保存草稿不创建业务数据。只有勾选内容确认并点击“确认生成”才写入。生成后的入口指向对应模式；重复提交返回原生成结果，不再次创建。删除对话不删除已经生成的计划。

## 调用和计次

DeepSeek 使用固定官方地址 `/chat/completions`、模型 `deepseek-flash`、`response_format=json_object`，显式关闭思考模式并限制输出 token。不提供工具执行能力、不跟随重定向、不自动重试、不允许客户端指定上游地址。接口形状依据 [官方对话接口](https://api-docs.deepseek.com/api/create-chat-completion/) 和 [JSON 输出说明](https://api-docs.deepseek.com/guides/json_mode/)。

提交立即返回 202 与任务 ID，前端约每 1.5 秒查询会话。异步任务在数据库持久保存，关闭页面不取消已接收请求。每个账号最多一个排队或处理中的请求；默认全局最多 2 个执行、4 个排队，防止单个成员占满小服务器。

任务准入与额度预占在同一短事务中完成。同一账号请求键复用同一条任务；不同内容复用键返回 409。外部 HTTP 等待不持有数据库锁。AI 路径不使用普通业务响应幂等缓存、不进入离线队列或私有离线快照。

成功回复计1次；修复启用且满足已知输出／用量／剩余预算条件时，最多额外修复一次，期间不释放预占；最终明确失败才退回。超时、连接中断或写入结果不确定时记为UNKNOWN，保留当日占用，不自动重试。UNKNOWN当日不会自动退款，次日新额度独立计算。重启后，超过超时宽限期的RUNNING转UNKNOWN，不重新调用；尚未开始的QUEUED可继续调度，服务关闭时退回预占。

普通请求正文最多256000字节；草稿保存、手动批次、协作预检／接受例外允许至多1MiB，再执行各自128000／160000字符校验。模型响应仍最多256000字节。单条用户消息最多8000字符，默认会话上下文最多16000字符、输出最多4096 token，包含当前消息、草稿和近期对话；超限先舍弃最旧对话，仍超限则拒绝调用并提示手工编辑，不悄悄截断当前草稿。输出截断、空内容、字段错误、模式错误、日期越界、休息日排期和循环依赖均拒绝。

## 草稿与业务一致性

V15 新增 `ai_sessions` 和 `ai_jobs`，保留 V14 额度账本。V16 将 MySQL 的 `draft_json` 扩为 MEDIUMTEXT，使合法大草稿不再受 TEXT 的 64 KiB 限制；H2 使用 CLOB。会话使用 version 防止多设备覆盖；正在处理时禁止修改草稿。生成操作将新业务记录和会话生成结果放在同一个事务中，任何一项写入失败都整体回滚。

目标路线以自由推进模式创建，有明确前置关系的步骤使用 EXPLICIT 依赖，并将草稿临时 ID 映射为真实记录 ID。周期计划保留用户选择的休息日，任务必须在日期范围内且不落在所选休息日；今日待办独立写入待办表。

已有对象调整使用独立的同意入口：周期计划详情、所选目标路线及单条未完成待办的“AI 调整”。V17 保存服务器私有快照和内部标识绑定，只给模型发送所选对象的草稿及不透明局部标识，不扫描全账号内容，也不发送执行备注。未同意时不载入，不调用模型。

修改建议逐项展示原内容、新内容、新增项以及保留事项和执行历史保护数量。允许手工编辑或继续讨论，但必须先保存草稿、勾选确认，再点击“确认应用修改”。原事项、阶段和相对顺序必须保留；不能删除旧内容或删除后重建。完成、开始、计时、执行备注和验收进度涉及的事项全部锁定。周期起点不变、终点只能延长，保护历史日期与复盘；路线未修改的阶段说明、继承依赖、验收字段等原样保留。

提交前锁定并核对原对象、全部事项、进度、计时汇总、阶段和依赖快照，而非仅检查父对象版本。过期快照在调用模型之前返回 409，不占额度；应用前冲突也返回 409，保留建议供参考，不覆盖另一设备修改。批量业务修改与应用记录同事务，失败整批回滚，重复确认返回原结果。回收站内容不恢复、不改写，整条路线含回收站依赖仍要通过无环校验。本机有任何待同步操作或冲突时，先处理队列，不能清除队列来应用 AI 建议。

## 保存与删除

每个账号最多保留 20 个会话，每个会话最多 30 轮。在线会话从创建起保留 30 天，到期后由清理任务删除；用户也可主动删除。正在处理的会话先完成或进入 UNKNOWN，再清理。每次请求使用的重复上下文在任务结束时清除。额度账本和操作指纹保留至少 90 天，不包含对话原文；无任务引用且超过 90 天的记录分批清理。过期会话不能重新提交，所以清理不允许旧会话重新调用；不能依赖旧请求键跨过保留期继续重放。

数据库备份可能包含到备份时点的会话副本，随备份保留策略到期清理；用户界面的删除不等于已经删除历史备份。DeepSeek 对其收到数据的处理以官方适用政策为准，不将本平台在线保留期限当作第三方承诺。生产日志不得启用请求正文、Authorization 或上游响应正文打印。

## 故障降级

服务未开启、额度耗尽或上游失败时，原有手动创建和业务同步不依赖 AI。已有草稿保持可查看、编辑、保存和确认。超时后先刷新核对结果，不自动重复付费请求。

用户也可在“给外部 AI 的格式说明”复制提示词，在外部工具生成 schemaVersion 1 JSON，再使用“导入外部 AI 草稿”校验和预览。导入和手工编辑不扣 AI 次数。当前不部署个人 PC 中转或客户端小模型，也不自动切换到另一个付费供应商。

## 服务器密钥配置

用户已准备官方 API Key，密钥仍由用户自行保管，未交给聊天、Git 或客户端。新环境初始化仍保留 `AI_ENABLED=false` 和默认额度 0 的安全默认值；当前生产环境已启用 AI，并于 2026 年 10 月 16 日通过管理员页面把数据库内的默认额度保存为 20。不会修改已执行迁移的校验和，也不会在每次升级时把管理员设置覆盖为 20。

`scripts/configure-ai-secret.sh` 已核对 SHA256 并同步到隔离候选目录，用户已通过隐藏输入保存密钥。需要新环境初始化时，由维护者先同步已审查脚本，再在 **FinalShell 的 ECS SSH 终端**运行，不是在 Windows PowerShell 中运行：

```sh
sudo sh /home/oyts/plan-platform/ai-candidates/0.1.10-ai-20261016-0015/scripts/configure-ai-secret.sh
```

脚本只接受交互式隐藏输入，拒绝命令行参数，不从环境变量读取密钥。它根据正在运行的非 root 后端识别 UID/GID，将密钥保存到 `/etc/plan-platform-ai/deepseek-api-key`，主机目录 root 0700、文件由后端 UID/GID 持有且权限 0600。已有文件不会读取或覆盖；轮换须另行确认。脚本不启用 AI、不重启容器、不调用 DeepSeek。

候选版本部署前须再次核对后端 UID/GID；如果镜像身份改变，不得用放宽所有用户读取权限的方法解决。容器内只读挂载地址为 `/run/secrets/deepseek-api-key`，用已有 `docker-compose.ai-secrets.yml` 叠加。先保留开关 false，验证挂载可读（只运行 `test -r`，不要 `cat` 密钥）。不要把 API Key 上传网盘、写入公开仓库、放在前端变量中或截图发到聊天。

## ECS 隔离验收

候选目录为 `/home/oyts/plan-platform/ai-candidates/0.1.10-ai-20261016-0015`。`scripts/ai-candidate.sh prepare` 先备份真实数据库，再创建随机后缀的 `plan_acceptance_*` 数据库、独立数据库用户和独立 JWT 配置。候选 API 仅监听 `127.0.0.1:43144`，内存上限 480 MiB，并发 1、排队 1，不更改 Nginx、current、正式 Compose 或生产数据库结构。正式用户不能用原登录凭证访问候选服务。

候选默认关闭 AI。专用管理员通过一次性引导令牌注册，两个普通合成账号通过邀请注册；不开放注册开关。凭据仅保存在服务器候选目录的 0600 文件中。以下命令只在 **服务器 SSH 终端**执行：

```sh
cd /home/oyts/plan-platform/ai-candidates/0.1.10-ai-20261016-0015
python3 scripts/ai-mysql-acceptance.py
```

默认验收不调用 DeepSeek，检查迁移、关闭时的手动导入、80 条大草稿保存、三模式确认生成、用户隔离、409、重复确认、路线依赖，以及第二条待办被数据库约束拒绝时整批回滚。测试 SQL 显式使用 utf8mb4，避免中文约束文本被错误解码。

只有默认验收通过且用户准备好密钥后，才允许挂载密钥并启用 **候选**：

```sh
sudo sh scripts/ai-candidate.sh enable
python3 scripts/ai-mysql-acceptance.py --real-max-calls 5
```

启用脚本核对非 root 镜像身份、密钥文件所有者和 0600 权限，只读挂载；不读取或打印密钥，也不主动发送请求。配置变化前如有 QUEUED/RUNNING 请求会拒绝重启，不中断或重放付费请求。

真实验收最多提交 5 个独立请求：模式推荐、路线草稿、路线修订、周期计划、今日待办。只向普通合成账号授予 5 次额度，默认额度仍为 0，结束后暂停该账号。每个请求测试相同操作键的并发重放，不新增独立调用。请求计数在提交前落盘；有启动标记时拒绝再次执行，失败不自动重试。不能为“让测试通过”删除标记后反复运行。模型回复和账号资料不上传 GitHub。

验收后备份候选数据库，在新 `plan_restore_*` 库中核对全部表校验和，再停止候选以释放内存。数据库、备份、私有配置和验收结果保留，不删除生产或历史服务。
