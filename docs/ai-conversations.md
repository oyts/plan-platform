# AI 对话与草稿生成

本阶段完成 AI 新建规划的本地开发：通过对话选择模式、生成及多次修改草稿，用户预览确认后，一次性创建周期计划、目标路线或今日待办。Web、Windows、Android 共用业务源码。本阶段没有发布安装包或升级云端，正式版本仍为 0.1.9，真实 DeepSeek 调用及 MySQL 8.4 发布前验证尚待完成。

## 用户操作

“AI 规划”位于电脑导航和手机“更多”菜单，三种业务的新建位置也分别提供 AI 构建入口。直接进入时可以先让 AI 推荐模式；从具体模式进入时表示用户已经选择该模式。

第一次发送前必须同意将本次对话与草稿交由 DeepSeek 处理。服务只发送当前对话、最近的必要上下文和当前草稿，不读取已有私人计划，不发送账号密码或 API Key。用户应避免输入敏感资料。

AI 推荐不会自动切换模式。尚未选择模式时，只能讨论和推荐，不能提交草稿。选择后可反复交流，AI 每次返回完整修订草稿，保留没有要求改动的部分。模型输出必须通过服务端校验；无效输出不替换已有草稿。

用户可编辑规划名称、任务标题、说明、日期、预计用时、周期休息日、路线阶段名称、步骤所属阶段和前置依赖，也可在草稿里增删步骤。每组显示 10 项，最多 100 项。未保存修改时，不能继续 AI 修改或确认生成；刷新、切换及离开页面会提示未保存内容。模型输出不是事实保证，具体内容和时间安排仍需用户核对。

保存草稿不创建业务数据。只有勾选内容确认并点击“确认生成”才写入。生成后的入口指向对应模式；重复提交返回原生成结果，不再次创建。删除对话不删除已经生成的计划。

## 调用和计次

DeepSeek 使用固定官方地址 `/chat/completions`、模型 `deepseek-flash`、`response_format=json_object`，显式关闭思考模式并限制输出 token。不提供工具执行能力、不跟随重定向、不自动重试、不允许客户端指定上游地址。接口形状依据 [官方对话接口](https://api-docs.deepseek.com/api/create-chat-completion/) 和 [JSON 输出说明](https://api-docs.deepseek.com/guides/json_mode/)。

提交立即返回 202 与任务 ID，前端约每 1.5 秒查询会话。异步任务在数据库持久保存，关闭页面不取消已接收请求。每个账号最多一个排队或处理中的请求；默认全局最多 2 个执行、4 个排队，防止单个成员占满小服务器。

任务准入与额度预占在同一短事务中完成。同一账号请求键复用同一条任务；不同内容复用键返回 409。外部 HTTP 等待不持有数据库锁。AI 路径不使用普通业务响应幂等缓存、不进入离线队列或私有离线快照。

成功回复计 1 次；明确失败或无效输出退回预占，不自动再调用。超时、连接中断或写入结果不确定时记为 UNKNOWN，保留当日占用等待核实。UNKNOWN 当日不会自动退款，次日新额度独立计算。重启后，超过超时宽限期的 RUNNING 请求转为 UNKNOWN，不重新调用；尚未开始的 QUEUED 请求可以继续调度，服务关闭时退回预占。

请求正文最多 256000 字节，模型响应最多 256000 字节。默认会话上下文最多 8000 字符，包含当前消息、草稿和近期对话；超限先舍弃最旧对话，仍超限则拒绝调用并提示手工编辑，不悄悄截断当前草稿。输出截断、空内容、字段错误、模式错误、日期越界、休息日排期和循环依赖均拒绝。

## 草稿与业务一致性

V15 新增 `ai_sessions` 和 `ai_jobs`，保留 V14 额度账本。会话使用 version 防止多设备覆盖；正在处理时禁止修改草稿。生成操作将新业务记录和会话生成结果放在同一个事务中，任何一项写入失败都整体回滚。

目标路线以自由推进模式创建，有明确前置关系的步骤使用 EXPLICIT 依赖，并将草稿临时 ID 映射为真实记录 ID。周期计划保留用户选择的休息日，任务必须在日期范围内且不落在所选休息日；今日待办独立写入待办表。

本轮只新建，不调整或删除已有真实任务。因此不能凭一份新草稿覆盖历史、完成进度或现有离线队列。已有计划的 AI 节奏调整仍待下一阶段，实现前必须逐项核对所有权、任务与进度版本、完成/历史保护及变更预览，不能只检查计划版本。

## 保存与删除

每个账号最多保留 20 个会话，每个会话最多 30 轮。在线会话从创建起保留 30 天，到期后由清理任务删除；用户也可主动删除。正在处理的会话先完成或进入 UNKNOWN，再清理。每次请求使用的重复上下文在任务结束时清除。额度账本和操作指纹保留至少 90 天，不包含对话原文；无任务引用且超过 90 天的记录分批清理。过期会话不能重新提交，所以清理不允许旧会话重新调用；不能依赖旧请求键跨过保留期继续重放。

数据库备份可能包含到备份时点的会话副本，随备份保留策略到期清理；用户界面的删除不等于已经删除历史备份。DeepSeek 对其收到数据的处理以官方适用政策为准，不将本平台在线保留期限当作第三方承诺。生产日志不得启用请求正文、Authorization 或上游响应正文打印。

## 故障降级

服务未开启、额度耗尽或上游失败时，原有手动创建和业务同步不依赖 AI。已有草稿保持可查看、编辑、保存和确认。超时后先刷新核对结果，不自动重复付费请求。

用户也可在“给外部 AI 的格式说明”复制提示词，在外部工具生成 schemaVersion 1 JSON，再使用“导入外部 AI 草稿”校验和预览。导入和手工编辑不扣 AI 次数。当前不部署个人 PC 中转或客户端小模型，也不自动切换到另一个付费供应商。

## 服务器密钥配置

用户已准备官方 API Key，密钥仍由用户自行保管，未交给聊天、Git 或客户端。`AI_ENABLED=false` 和初始默认额度 0 继续保持安全默认值。

本仓库提供 `scripts/configure-ai-secret.sh`，但本轮尚未把该脚本同步到服务器，不能直接在旧版本目录中执行不存在的文件。部署准备时先由维护者将审查后的代码同步到 ECS，再在 **FinalShell 的 ECS SSH 终端**运行，不是在 Windows PowerShell 中运行：

```sh
sudo sh scripts/configure-ai-secret.sh
```

脚本只接受交互式隐藏输入，拒绝命令行参数，不从环境变量读取密钥。它根据正在运行的非 root 后端识别 UID/GID，将密钥保存到 `/etc/plan-platform-ai/deepseek-api-key`，主机目录 root 0700、文件由后端 UID/GID 持有且权限 0600。已有文件不会读取或覆盖；轮换须另行确认。脚本不启用 AI、不重启容器、不调用 DeepSeek。

候选版本部署前须再次核对后端 UID/GID；如果镜像身份改变，不得用放宽所有用户读取权限的方法解决。容器内只读挂载地址为 `/run/secrets/deepseek-api-key`，用已有 `docker-compose.ai-secrets.yml` 叠加。先保留开关 false，验证挂载可读（只运行 `test -r`，不要 `cat` 密钥）。不要把 API Key 上传网盘、写入公开仓库、放在前端变量中或截图发到聊天。

## 待完成的发布步骤

1. 使用高于 0.1.9 的新版本号统一三端元数据，不重发旧版本不同字节的安装包。
2. 备份当前真实数据库，在独立 MySQL 8.4 数据库验证 V14/V15、额度并发、批量写入及恢复；不覆盖生产库。
3. 用户自行隐藏输入密钥，在隔离候选服务中启用官方调用，为专用验收账号配置少量次数。真实请求可能计费，应限定范围，不自动批量消耗额度。
4. 完成真实中文多轮规划与输出质量验收，再按用户指定范围做原生新增功能测试；需要 Android USB 时再通知连接。
5. 按原流程签名、备份、发布更新源、切换云端入口并核验，保留回滚版本。官网 APK 和公开注册保持原策略，不随 AI 功能开放。

## 定向验证

本地定向测试累计 27 项后端、5 项前端单元、10 项浏览器用例通过；Web、Windows/Android 共享前端构建及影响清单自测通过。隐藏输入脚本已做 shell 语法检查，尚未在 ECS 执行。界面沿用 frontend-design 的 Swiss 方向：白底、蓝色、细分隔线，电脑并列对话与草稿，手机上下排列。

只跑 `scripts/release-test-scope.json` 中本阶段新增及直接受影响功能。后端包括官方请求形状的回环假服务、模式确认、三模式生成、草稿版本、授权隔离、去重计次、队列上限、失败保留、过期清理、批量回滚和原业务幂等单用例。浏览器验证桌面/手机布局、三入口、重开恢复、手工修改、确认防误触、冲突保留和无 AI 导入。共享前端构建不等于 EXE/APK 真机或真实官方模型通过。

mvn -f backend/pom.xml '-Dtest=AiConversationIntegrationTest,DeepSeekProviderTest,AiFoundationTest,AiQuotaIntegrationTest,AuthPlanIntegrationTest#idempotencyKeysReplayCompletedWritesAndRejectDifferentPayloads' test
