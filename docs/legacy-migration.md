# 旧版数据迁移

## 目标

把计划控制台 1.x 的单用户 JSON 备份导入当前登录账号，同时保留原始快照、迁移报告和可回滚能力。整个批次在一个数据库事务中执行；任意关系数据写入失败时，不会留下半批数据。

## 推荐操作

1. 在旧版计划控制台打开“设置与备份”，重新导出 JSON。
2. 新导出的文件包含 `migrationCatalog`，其中保存暑假计划及内置吉他、项目升级主线的任务定义。
3. 在新平台“设置与旧数据迁移”选择文件，先检查预检数量和警告。
4. 点击“确认迁移”。相同文件重复提交只返回已有报告，不会重复创建数据。
5. 检查计划、任务、计时、复盘和主线；发现问题时在迁移历史中回滚本批，再修正源数据并重新导入。

## 关系数据范围

- 计划、标签、任务；
- 任务状态、验收项、备注、延期与跳过原因；
- 计时流水和累计时长；
- 每日复盘；
- 内置及自定义主线、主线步骤和完成状态。

闸门已迁为里程碑，任务模板迁入用户模板库，保留对应的勾选和备注。旧版回收站和删除标记尚未转为新版软删除记录，仅保存在 `legacy_imports.payload` 原始快照中，预检及迁移报告会明确提示这一边界。

### 未发布：历史问题收口中的新导入转换

2026年10月22日源码已补齐新导入批次的四类快照（计划、路线、步骤、标签）转换，保留删除时刻及步骤位置；永久删除标记只用于抑制旧备份里的陈旧副本，不伪造没有正文的可恢复记录。恢复沿用新版规则，不自动改写已重新分配的任务标签。旧运行计时不会因回收站恢复而自动继续。原始文件及校验和不改变，所有关系仍在同一导入事务内写入。

这不是现有0.1.19生产能力，也不会自动补齐以前已经完成的迁移批次。旧批次预检`GET /api/migrations/legacy/{importId}/recycling-preview`及确认补迁`POST /api/migrations/legacy/{importId}/recycling-supplement`已补源码和共享页面；需要预检指纹、UUID操作键、显式确认，回执与新增记录在同一事务。只补缺失回收站正文，不用旧永久删除标记删除当前记录。现有路线的已删除步骤追加到顺序末尾，不移动用户现有步骤，原位置保留在快照。回滚本批涵盖原导入和补迁，不是只撤销补迁。不要为使用新转换而回滚真实批次、丢失后续编辑。当前定向验收与剩余门槛见[历史收口记录](historical-closure-progress.md)。

## API

- `POST /api/migrations/legacy/preview`：校验并返回数量、警告、错误和 SHA-256 校验值；
- `POST /api/migrations/legacy/import`：执行幂等迁移；
- `GET /api/migrations/legacy`：查看当前账号迁移历史；
- `POST /api/migrations/legacy/{importId}/rollback`：删除本批创建的计划和主线，保留快照；
- `POST /api/migrations/legacy-snapshot`：兼容旧流程，仅保存原始快照。

每个账号同一时间只允许存在一批 `COMPLETED` 迁移。需要改用另一份备份时，应先回滚原批次，避免同一旧版实体被重复导入。
