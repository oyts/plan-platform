# 页面切换与返回位置优化

本阶段修复长页面切换后沿用旧滚动位置的问题。实现进入 Web、Windows、Android 的共享 Vue 源码，保留原有白底蓝色网格和业务数据结构。现随 0.1.9 发布，实际原生验收状态见 [0.1.9 发布记录](release-019.md)。

## 导航行为

- 进入不同页面或另一节教学时，立即回到页面顶部，并把程序焦点移到主内容区域。没有平滑滚动动画，焦点移动不额外触发浏览器滚动。
- 同一页面更改查询参数（例如选择路线或日程计划）不强制回顶，也不抢走表单焦点。
- 浏览器后退/前进优先恢复对应历史记录的位置。列表异步加载可能改变页面高度，因此最多观察两秒布局变化，修正浏览器滚动锚定导致的偏移。
- 等待恢复期间，一旦用户触摸、滚轮、鼠标按下、键盘输入或再次切换路由，就停止旧恢复任务，并清理观察器、事件监听和定时器。

列表在两秒后才返回、内容已删除或高度变短时，不保证恢复到原先完全相同的内容位置。用户操作始终优先，不会持续把用户拉回旧位置。模式独立记忆仍保存原页面地址，不新增跨账号持久化滚动记录；教学进度、离线队列、认证和更新策略不变。

## 复现与验证

手机视口中从长计划列表底部打开“更多 → 使用教学”，原实现会停在教学页下方；修复前测试实际测得新页 `scrollY=881`。仅增加立即回顶还不能解决历史返回：列表加载后会重新挤动位置，故另有延迟 API 回归。

新增自动测试使用独立内存数据库和随机合成账号，不连接生产数据库。导航用例覆盖桌面与手机视口的新页回顶、主内容焦点、教学切换、延迟列表后退恢复、快速再次导航取消和官网原生锚点链接。

2026 年 10 月 15 日开发阶段的历史验收：前端 167 项单元测试通过，其中导航策略 11 项；完整浏览器回归 88 项通过、6 项按既有规则跳过（仅手机项目运行的布局用例），无失败。此后维护者调整为日常版本仅验证影响范围，0.1.9 发布只执行导航单元 11 项和桌面/手机网页导航各 4 项，不重复完整业务回归。Web、Windows 共享前端、Android 共享前端构建通过，已检查修复后的两种视口截图。

在项目 `web` 目录运行：

```powershell
npm test -- src/router/scroll.test.ts
npm run build
npx playwright test e2e/navigation.spec.ts
npm run build:desktop-web
npm run build:android-web
```

沿用项目 Java 21、Node 22、独立验收 API JAR 和 Playwright 浏览器配置，见 [浏览器与原生回归说明](native-regression.md)。浏览器截图与日志位于被 Git 忽略的 `web/test-results/` 和 `web/playwright-report/`。

## 发布边界

0.1.9 已以新版本及 Android 构建号 14 重新签名发布，不清理原数据，不重发同版本不同内容的签名包。Windows 官网和更新源、Android 登录后的受限更新通道分别保留回滚材料，详见发布记录。

网页视口和共享前端构建不等同于 EXE 或 APK 真机通过；本阶段不据此宣称系统返回键或其他厂商手机均已验收。
