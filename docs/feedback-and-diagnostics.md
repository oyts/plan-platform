# 反馈与脱敏诊断

阶段一在三端共用源码中提供“反馈与诊断”入口。共享源码与连接桥定向用例已通过，当前仍为开发候选，尚未部署至正式 0.1.14，也未完成原生界面验收。

## 用户流程

从主导航或手机“更多”进入，填写分类、摘要、操作步骤、期望和实际结果。可选诊断默认不附带，主动生成后先查看；发送前还须核对完整内容并勾选同意。

反馈仅本人和管理员可查看。状态依次可设为待处理、处理中、待补充、已解决、已关闭；用户补充信息会重新进入待处理。两端同时修改时以版本拒绝过期写入，保留当前补充文字，读取最新记录后再人工确认。

离线时可手动保存当前服务器和账号专属的本机草稿，重开后恢复，不自动发送，也不加入任务同步队列。发送前先持久保存提交编号和完整内容；响应丢失时锁定原内容并重试同一编号，服务端不会重复建单。若本机存储不可用，停止发送并提示，避免失去重试依据。

## 隐私边界

诊断白名单为客户端版本、已知服务版本及 API 版本、平台、发生时间、错误分类、随机请求关联编号、队列数量和冲突数量。服务端再次校验字段及长度，拒绝额外字段。网络异常不能可靠区分网络和 TLS 时使用共同分类，不猜测证书原因。

不自动收集账号、密码、令牌、Key、邀请链接、AI 原文、任务标题、设备序列号、网络地址、原始日志或截图。首版无附件。用户主动填写的自由文本仍可能包含隐私，因此发送前提示并要求确认。仅导出的诊断 Markdown 也应自行妥善保管。

## 接口与一致性

| 范围 | 接口 | 约束 |
| --- | --- | --- |
| 本人 | `GET/POST /api/feedback`、`GET /api/feedback/{id}` | JWT 所有权、分页、响应 no-store |
| 补充 | `POST /api/feedback/{id}/replies` | 版本检查，消息与状态同事务 |
| 管理 | `GET /api/admin/feedback`、`GET/PUT /api/admin/feedback/{id}` | ADMIN 服务端校验，关闭或需补充必须有说明 |

V20 新增反馈与消息表，不修改已有业务记录。每账号每天最多新建 10 条反馈，每条最多 100 条补充与处理消息；日界按北京时间计算。创建用账号行锁串行检查限额，以账号加操作编号唯一约束及正文指纹作持久防重；相同编号不同内容返回 409。修改锁定反馈后比较版本，再一次性写入消息、状态和活动计数。

`X-Request-ID` 仅接受 UUID，否则服务端重新生成；不接受任意文字或 URL，也不回传凭据。CORS、Windows 与 Android 受限连接桥只增加这一名称，不放开 Cookie、Host 或任意头。

## 定向验收

阶段内集中覆盖本人隔离、管理员权限、白名单拒绝、重复提交、日限额、分页、版本冲突、消息原子性、离线草稿重开、响应丢失重试、管理员手机布局和纯文本呈现。相关用例列于 `scripts/release-test-scope.json`；结果与剩余门槛记录于 `docs/roadmap-progress.md`。不调用付费 AI、不发送真实邮件、不用真实私人计划作样本。
